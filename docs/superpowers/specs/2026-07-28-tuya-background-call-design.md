# 涂鸦监控与对讲后台保活设计

**目标：** 涂鸦发起监控或对讲后，室内机仍可使用低风险功能；进入会抢占音频、视频解码或网络会话的功能时拒绝操作，保证当前音频传输不中断。

## 背景与根因

所有页面跳转都通过 `goto_layout()` 执行。该函数在进入目标页面前调用当前页面的 `quit()`。监控页面的退出处理会调用 `audio_talk_close(true)`、清除通话标志并发送对讲结束命令。因此，涂鸦监控或对讲期间离开监控页面会错误地结束仍应保持的音频会话。

## 会话定义

新增一个由监控模块维护的“活动涂鸦会话”判断接口。它在涂鸦监控进入事件后生效，并覆盖以下两种状态：

- 涂鸦正在监控，音频收发链路已建立；
- 涂鸦正在对讲，`is_tuya_talking` 为真。

会话只在涂鸦明确结束、当前通话正常挂断，或需要强制清理的系统事件中结束。页面切换本身不得结束会话。

## 页面与功能策略

### 允许

- 主界面、待机/时间显示等只显示状态的页面；
- 门锁、门禁等不重置音视频或网络通道的即时控制操作；
- 纯显示的状态信息。

允许从监控页切换到这类页面。切换仅隐藏监控 UI，不关闭音频、不清除涂鸦事件回调、不改变活动会话状态。返回监控页时应复用已存在的会话，不能重复打开音频设备或重新创建网络收发任务。

### 禁止

- 媒体、事件录像、文件列表、视频回放、照片浏览、音乐播放；
- Wi-Fi 扫描、连接、断开、配网和涂鸦重新注册；
- 室内机/门口机升级、重启及其他会改变系统运行状态的操作；
- 再次发起监控、CCTV、室内机对讲、转呼等并发音视频业务；
- 会开启视频解码、缩略图解码、音频播放或修改当前网络会话的页面。

拒绝时保持在原页面，显示统一的“通话中，暂不可使用此功能”提示；不得先执行当前页面退出清理。

## 实现方案

1. 在监控模块提供只读的活动涂鸦会话状态接口，并将当前页面退出分为：
   - `UI` 切换：保留音频、网络与涂鸦事件回调；
   - 会话结束：执行现有 `audio_talk_close(true)`、通话状态清理和事件回调恢复。
2. 在 `goto_layout()` 的当前页面 `quit()` 之前调用统一导航保护函数。
   - 非活动会话：保持现有行为；
   - 活动会话且目标为禁止页面：提示并返回失败；
   - 活动会话且目标为允许页面：继续跳转，并通知监控模块执行仅 UI 的退出路径。
3. 对无需跳转即可破坏会话的动作增加相同检查：Wi-Fi 连接/断开、配网、升级、重启及并发音视频启动入口。
4. 为允许页面提供通话状态提示和“返回监控”入口；首次实现使用已有消息/状态栏控件，避免引入悬浮窗框架。

## 异常与优先级

- 涂鸦端主动结束监控或通话时，无论室内机当前在哪个允许页面，都执行完整会话清理；
- 来电、报警和系统强制事件保留现有优先级，必要时可结束后台会话；
- 活动会话期间禁止执行任何会替换当前音频输入、输出、解码器或网络连接的操作；
- 现有非涂鸦监控和普通室内对讲逻辑不改变。

## 验收标准

1. 涂鸦监控/对讲期间进入主界面或时间显示，音频持续传输，涂鸦侧不收到挂断。
2. 通话期间尝试进入媒体、回放、Wi-Fi、升级、CCTV 或室内机对讲，页面不跳转并显示提示。
3. 通话期间尝试执行 Wi-Fi 连接/断开、配网、重启或升级，操作不执行并显示提示。
4. 涂鸦端挂断后，后台会话清理完成，所有页面与功能恢复可用。
5. 非涂鸦监控与现有室内机对讲流程保持原有行为。
