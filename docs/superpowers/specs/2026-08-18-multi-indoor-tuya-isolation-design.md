# 多室内机 Tuya 监控隔离设计

日期：2026-08-18

## 目标

两台室内机共用门口机时，A 室内机连接手机 Tuya 并进入监控后：

- B 室内机仍可正常操作本地界面；
- B 室内机可进入同一个门口机的视频监控；
- B 室内机点击监控页通话按钮时，不打开本地音频，提示“手机监控中”；
- A 室内机现有 Tuya 视频、音频和保活链路不受影响。

## 根因

门口机 `talk_busy` 是总线级状态。A 的手机 Tuya 监控会使门口机状态包置位 `talk_busy`，B 收到状态后存在三处误处理：

1. busy 回调可能把 B 当前页面强制切回待机；
2. 监控通道入口把 `outdoor_busy` 当作禁止视频监控的条件；
3. 待机触摸曾直接使用总线 `talk_busy`，导致 B 表现为触摸无响应。

当前工作树中的 `src/layout/layout_standby.c` 已包含第 3 点的局部修复，本次保留该修改并补齐 busy 回调、监控入口和通话按钮策略。

## 方案

### UI busy 事件

门口机总线 busy 只表示共享媒体资源正在使用，不再作为强制中断室内机 UI 的依据。`main_device_monitor_busy_func()` 和监控页 busy 回调收到事件后不再把 B 切换到待机。

### 视频监控入口

`tuya_session_local_monitor_allowed()` 调整为：

- 本机正在 Tuya 双向通话时禁止本机进入本地监控；
- 单纯的门口机 `outdoor_busy` 不禁止视频监控；
- A 手机监控期间，B 可进入相同门口机查看视频。

保留现有函数参数以减少调用点修改，但策略不再使用 `outdoor_busy` 和 `local_video_client_active` 决定视频入口。

### 监控页通话按钮

增加纯策略函数判断本地通话是否允许。以下任一条件成立时拒绝打开音频：

- 本机存在 Tuya 视频客户端；
- 本机处于 Tuya 监控状态；
- 当前门口机上报 `talk_busy`。

拒绝时复用 `STR_PHONE_MONITORING` 弹窗。由于现有协议没有携带占用来源，B 无法区分“手机监控”和“其他终端占用”，因此总线 busy 统一显示“手机监控中”。

## 测试设计

在 `src/layout/tests/` 中使用纯策略单元测试覆盖：

1. `outdoor_busy=true`、本机无 Tuya 通话时，允许进入视频监控；
2. 本机 Tuya 通话时，不允许进入视频监控；
3. 门口机 `talk_busy=true` 时，不允许开启本地通话；
4. 本机 Tuya 客户端或 Tuya 监控状态存在时，不允许开启本地通话；
5. 没有任何占用时，允许开启本地通话；
6. 不论本机是否有 Tuya 会话，总线 busy 事件都不应中断本地 UI。

测试必须先按旧实现运行并观察预期失败，再实现最小策略修改并重新运行通过。

## 验证场景

1. A 手机进入 Tuya 监控，B 在首页、设置、记录等页面操作不被强制退出；
2. B 进入 A 正在使用的同一门口机监控，视频正常显示；
3. B 点击通话按钮，显示“手机监控中”，不创建音频发送/接收任务；
4. A 手机退出 Tuya 监控后，B 通话按钮恢复；
5. A 手机 Tuya 画面和音频在 B 页面进入、退出过程中保持连续。

## 非目标

- 不修改门口机通信协议；
- 不实现多个室内机同时向门口机发送双向音频；
- 不改变 A 室内机已有的 Tuya 共享视频、共享音频和 keepalive 策略。
